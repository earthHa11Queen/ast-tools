# 鏡の原理 基本仕様

## 基本原則

鏡の原理は、入力値の正常領域を定義し、その境界および正常領域の外側を体系的にテストするためのテスト設計方式である。  
テスト観点はX、Y、Zの3軸で表現する。  

## X軸

Xは値そのものの種類、性質、文字種、データ構成等を表す。  
例：
- 半角文字
- 全角文字
- 英字
- 数字
- 記号
- 漢字
- カナ
- 制御文字
- その他、値そのものの性質
具体的な利用可能観点は `mirror_x_axis.csv` を正式なカタログとする。  

## Y軸

YはXとして与えられる値に対する、
- 桁数
- 文字数
- 要素数
- 数量
- 最小境界
- 最大境界

等を表す。  
ソースコード側から明示的なmin/maxが取得できる場合はそれを境界として使用する。  
明示的な境界が存在しない場合は、言語データモデルとして事前定義されたテスト生成用の範囲を使用できる。  
Yとして適用可能であると決定論的に判定済みの候補は原則としてすべてテストする。  
具体的な利用可能観点は `mirror_y_axis.csv` を正式なカタログとする。  

## Z軸

Zは値が持つ、
- 意味
- 用途
- 文脈
- フォーマット
- 構造
- 特殊パターン
を表す。  

例えば同じSTRINGであっても、
- email
- host
- URL
- path
- password
- database name
等では意味的に適切なZが異なる。  
Zの選択は、ソースコードの名称、annotation、method context等を利用して判断する。  
根拠がないZを推測で適用してはいけない。  
具体的な利用可能観点は `mirror_z_axis.csv` を正式なカタログとする。  

## X・Y・Zの関係

X、Y、Zは異なる観点軸である。  
ただし、すべてのX、Y、Zを無条件に直積化してテストケースを生成してはいけない。  
目的はケース数を最大化することではなく、
- 必要な境界を漏らさない
- 必要な値種を漏らさない
- 必要な意味パターンを漏らさない
- 同じ目的のケースを重複させない
ことである。  

## ケース生成

原則として、各ケースは何を変化させているか説明できる状態にする。  
Xを確認するケースではXが主観点となる。  
Yを確認するケースではYが主観点となる。  
Zを確認するケースではZが主観点となる。  
複数軸を組み合わせることは許可するが、その組み合わせ自体に意味がある場合に限る。  

## 正常領域と異常領域

正常として定義された値の集合を基準とし、境界およびその外側を異常候補として扱う。  
ただし、正常・異常の最終判断が業務仕様に依存する場合は、ソースコードや入力された意味情報から判断可能な範囲のみ判断する。  
判断不能な仕様をAIが新しく作ってはいけない。  

## AIの役割

AIはMirror観点そのものを新規生成しない。  
AIは与えられたMirror候補から、
- 対象に意味的に適用できるもの
- 実際にテストケースとして必要なもの
を選択する。  
具体的なテスト値はAIが生成しない。  
具体値は後続の決定論的Data Generatorによって生成する。  

## Data Generatorの役割

Data Generatorは、
- targetId
- generatorTarget
- generatorRule
- convModel
- effectiveMin
- effectiveMax
- Mirror定義
等を入力として具体的なテストデータを生成する。  
Data Generatorは自然言語のケース内容を解析して生成ルールを決定してはいけない。  

## 正式カタログ

具体的なMirror IDおよび各候補の定義については、以下を正式カタログとする。  
- `mirror_x_axis.csv`
- `mirror_y_axis.csv`
- `mirror_z_axis.csv`
本仕様と各CSVが役割上異なる場合、本仕様はMirror全体の運用規則を示し、CSVは具体的な観点IDとその定義を示すものとして扱う。
